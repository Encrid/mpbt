# src/shared/sha256/sha256.c

This file makes a SHA-256 digest by the steps of FIPS 180-4: https://csrc.nist.gov/pubs/fips/180-4/upd1/final.
It reads no file. The caller gives the bytes, in one piece or in many.

## The steps

1. `sha256_start` sets the 8 words of section 5.3.3, and `length` and `used` to 0.
2. `sha256_add` copies bytes into `block`. When `block` is full, `compress` mixes it into `state`, and `used` is 0 again.
3. `sha256_end` adds the byte `0x80`, then zeros, until 56 bytes of a block are full.
4. The last 8 bytes of that block hold the length in bits, the most significant byte first. If they do not fit, one more block comes.
5. The digest is the 8 words of `state`, each with its most significant byte first.

`compress` makes the 64 words of the schedule from the 16 words of the block. Then it does the 64 rounds, with the constants of section 4.2.2.
`sha256_get_hex` writes each byte as 2 lower-case hexadecimal characters, then a zero byte.
`sha256.txt` of a release and `package.txt` use this form.

## The limits

`length` counts bytes in 64 bits. Thus a digest is right for each length up to 2 to the power 61 bytes.

## Functions

| Function | Result |
| --- | --- |
| `sha256_start` | Gives the first state. |
| `sha256_add` | Fills the block, and mixes each full one. |
| `sha256_end` | Pads the last block, and writes the digest. |
| `sha256_get_hex` | Writes the digest as text. |
| `compress` | Mixes one block into the state. |
