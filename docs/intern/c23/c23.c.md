# src/c23/c23.c

This file is the module `c23`, which runs on Bridge, with its exports and the system of the check `c23` of `docs/extern/mpbt_check.h.md`, *The checks*.

## The manifest

`mpbt:c23@<version> abi=3 config=none pinned=false reloadable=false`

`<version>` is the version of mpbt, and the host gives the other keys. The check has no settings, because the older spellings are a table of its code.

## The components

| Type | Written or read | Storage | on_unload |
| --- | --- | --- | --- |
| `mpbt:File` | Read | `BRIDGE_TABLE` | `BRIDGE_SWEEP` |
| `mpbt:Finding` | Written | `BRIDGE_TABLE` | `BRIDGE_SWEEP` |

`world_declare` of `src/shared/world/world.h` declares the 2 types, in this order.
`read` and `report` state the sweep too, so the order of the unloads changes nothing. A sweep removes an entity that has nothing left, and keeps each other entity.

## The systems

| Name | Phase | Terms | Changes |
| --- | --- | --- | --- |
| `c23` | `check` | `mpbt:File`, with `BRIDGE_READ` and `BRIDGE_AND`. | `mpbt:Finding` |

The system and each finding take the name `c23` from `CHECKS_NAMES` of `src/shared/checks/checks.h`.

## The steps of the system

1. `world_rows` gives each `mpbt:File` to `c23_check_file`.
2. The system gives 0.

Bridge fails the run of the system when it refuses a call, for example an `alloc` of a finding.

## Functions

| Function | Result |
| --- | --- |
| `init` | Declares `mpbt:File`, then `mpbt:Finding`, and adds the system `c23`. |
| `shutdown` | 0: the module keeps nothing. |
| `reload` | What `init` gives. Bridge does not reload a module with `reloadable=false`. |
| `c23` | The system: 0. |

The native names of the exports have the prefix `bridge_`, for example `bridge_c23`.
